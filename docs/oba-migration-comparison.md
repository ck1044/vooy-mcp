두 구현에서 서로 다른 임베딩 모델의 벡터는 섞지 않는다. ZIP에 저장된 과거 벡터는 provenance 확인을 위해 보관하며 기존 검색 공간에 넣지 않는다. 사용자 승인에 따라 이미지가 등록되면 현재 워커가 OpenRouter에 보내 새 직접 이미지 벡터를 생성한다.

`data/selected/manifest.json`의 선정 사진 100장과 파일 전체를 확인했다. 사진은 전부 JPEG이며 100장 모두 manifest SHA-256이 일치한다. 선정 목록의 날짜·도시는 모두 `synthetic`으로 표시되어 있고 해당 원본 100장에서는 EXIF 촬영일과 GPS가 발견되지 않았다. 출처의 라이선스는 전부 `Not specified`로 기록되어 있어 해당 기록을 그대로 보존한다. BTS 예시 갤러리는 `bts-daily` 컬렉션으로 구분한다. ZIP에는 PostgreSQL 덤프가 없으며 포함된 SQLite는 비어 있다. macOS 가상환경과 민감 설정을 포함한 원본 ZIP은 그대로 보관한다.

이식 검증에는 원본 SHA-256, MCP 이미지 블록과 사진 ID의 대응, 검색 결과 이미지 콘텐츠 인덱스, 다운로드 및 미리보기 서명, 삭제된 자료의 접근 제한, 다른 이미지와의 벡터 검색 품질, 실제 Vooy의 표시 여부를 포함한다.

## 검색 평가 및 범위

선정 100장을 OpenRouter 이미지 임베딩으로 색인한 뒤 ZIP의 검수 질문 중 가상 시간·장소·인물 필터가 없는 시각 질의 24개를 사용했다. 개발 6개 문항(정답 있음 4, 없음 2)의 상위 1개 코사인 점수에서 양성 최저와 음성 최고 사이 중간값을 최소 유사도 `0.608091`로 정했다. 기준을 고정한 별도 테스트 18문항에서는 정답 있는 13개가 모두 상위 3장에 포함됐고 정답 없는 5개가 모두 `no_match` 기준에 해당했다. 개발 문항은 4/4, 2/2였다.

이 결과는 이 작은 BTS 데이터셋과 해당 모델·전처리에 대한 평가다. 다른 사진 모음·모델·질문에 동일한 정확도를 보장하지 않는다. 기준은 `bts-daily` 컬렉션과 현재 Gemini Embedding 2 공간에만 기록한다. 컬렉션을 지정하지 않은 검색은 현재 활성 사진 전체가 이 한 컬렉션에만 속하는 경우에만 해당 컬렉션을 자동 선택한다. 개인 사진 등 다른 자료가 추가되면 자동 선택을 중단한다. 실제 Vooy 화면의 이미지 표시와 사진을 메시지에 첨부하는 동작은 MCP 응답 확인과 별도로 사용자 환경에서 확인한다.

`BTS 사진 보여줘`처럼 구체 장면 조건 없이 갤러리 전체를 요청하면 해당 컬렉션의 이미지를 최신순으로 반환한다. 검증된 기준이 없는 혼합 컬렉션 검색은 결과를 `candidates_unverified`로 표시한다. 날짜 조건에 해당하는 결과가 있더라도 촬영일 미상 후보가 있으면 별도 개수로 알린다.
