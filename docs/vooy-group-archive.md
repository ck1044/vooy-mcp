# Vooy 단톡방 기록 저장

확인일: 2026-11-07. 대상은 Vooy 단톡방에서 호출한 내 Vooy와 연결된 `Vooy 미디어 저장소`다.

## 대화와 이야기

단톡방에서 내 Vooy를 선택하고 보관할 내용을 지정한다. 예를 들면 다음과 같다.

> 이 방에서 방금 이야기한 여행 계획을 원문 그대로 Vooy 미디어 저장소에 저장해 줘. 제목은 가족 여행 계획, 출처는 Vooy 단톡방: 가족, 태그는 가족과 여행으로 해 줘. 저장된 자료 ID도 알려줘.

Vooy는 접근 가능한 최근 대화의 내용을 `save_text`로 전달한다. 요청에 원문·요약 중 원하는 형태와 저장 범위를 적으면 된다. 저장된 자료는 제목·태그·본문으로 검색하고 자료 ID로 다시 조회할 수 있다. 전체 대화 이력이 자동으로 수집되는 방식은 아니다.

2026-11-07 갤럭시 탭의 실제 단톡방에서 별도로 올린 시험 이야기의 원문을 `save_text`로 저장했다. Vooy가 응답한 자료 ID `테스트 자료 ID`와 저장소의 본문·출처·태그를 대조했다.

같은 방에서 일주일치 대화를 요청한 시험 자료 `테스트 자료 ID`도 저장소에 존재한다. Vooy의 답변에 따르면 실제로 읽을 수 있었던 11월 7일 대화만 담겼으며 일부 메시지와 이미지 원본은 빠졌다. 따라서 자료 제목의 기간을 저장 범위의 보증으로 사용하지 않는다.

## 사진

2026-11-07의 실제 시험에서 기존 단톡방 사진은 Vooy에 사진 알림으로 전달됐다. 사진을 호출 메시지에 함께 첨부했을 때는 Vooy가 이미지 내용을 볼 수 있었지만 MCP로 넘길 원본 파일이나 주소를 받지 못해 자동 원본 저장은 완료되지 않았다.

현재 사용할 수 있는 저장 경로는 업로드 페이지다. 내 Vooy에게 예를 들어 이렇게 요청한다.

> 이 방의 사진을 저장할 업로드 링크를 만들어 줘. 제목은 가족 여행 사진, 출처는 Vooy 단톡방: 가족, 태그는 가족과 여행으로 해 줘.

Vooy가 `create_upload`로 링크와 업로드 ID를 만들면 링크를 열고 사진 파일을 선택해 업로드한다. 서버가 파일을 검증한 뒤 자료 ID를 표시하며, `get_upload_status` 또는 `get_asset`으로 저장 상태·출처·태그·SHA-256을 확인할 수 있다. 사진을 단톡방에서 이미 보냈더라도 이 경로에는 파일 선택이 필요하다.

격리된 서버와 데이터베이스의 실제 브라우저 시험에서 시험 PNG를 선택해 업로드하고 출처·태그와 원본 SHA-256 `aebef368ebd189276cce75c12828c10a0c8bd0d3500bff34b08ca4842a48f8f5`의 일치를 확인했다.

실제 공개 MCP에서도 같은 시험 PNG를 업로드했다. 자료 ID는 `테스트 자료 ID`이며, 저장된 원본과 다운로드 파일의 SHA-256이 위 값과 일치했다. `단톡방테스트` 태그로 시험 이야기와 시험 사진이 함께 조회됐다.

갤럭시 탭의 실제 단톡방에서도 내 Vooy가 만든 링크를 열고 같은 PNG를 선택해 업로드했다. 자료 ID `테스트 자료 ID`의 SHA-256이 원본과 일치했다. 이 실기기 시험 당시 Vooy에 등록된 도구에 태그·출처 입력이 아직 반영되지 않아, 저장 직후 `update_asset_metadata`로 요청한 출처와 태그를 보완했다.

도구 갱신 후 다시 단톡방에서 요청해 발급된 링크로 사진을 올렸다. 최종 자료 ID `테스트 자료 ID`에는 요청한 제목·출처·태그가 업로드와 함께 저장됐고, D 드라이브 원본의 SHA-256도 같은 값으로 확인했다.

`create_upload`의 `tags`와 `source`는 새 파일에 적용된다. 기존 자료의 원본 교체는 기존 출처와 태그를 유지하며, 변경이 필요하면 `update_asset_metadata`를 사용한다. 업로드 링크가 만료되면 `get_upload_link`로 새 링크를 받을 수 있다.

공개 이미지 주소가 있으면 `import_from_url`로 가져올 수도 있다. 작업 상태는 `get_import_status`로 확인한다.
